# T14 observed-user session protocol

Status: **NOT_RUN**. Owner: product validation / appointed observer. This is a protocol, not evidence that sessions occurred. E04 remains unconfirmed. Automated role fixtures and registered synthetic database identities are not observed people.

Use separate analyst, reviewer, source-administrator and restricted-reader accounts. An independent reviewer must be a different canonical human from the analyst, not a second credential for the same person. Use a reviewed dataset and approved retrieval profiles; record any unavailable feed as unavailable.

For each participant, record a consented anonymous identifier, role, locale, timezone, browser/device, viewport/text enlargement, input method and accessibility needs. Record start/end time, completion, errors, recovery, assistance and a short participant explanation of what the output establishes. Do not include credentials or personal case text in evidence.

Give the analyst a question requiring an area and historical period. Observe whether they find a country/subdivision or enter signed coordinates, preserve exact geometry and timezone across tools, identify an unsupported period, resume a saved investigation, reach later catalog pages, inspect one aggregate's source records and recover from an expired read. Repeat a relevant step with Arabic source names and Arabic digits.

For imagery, ask the analyst to distinguish selected area, actual scene footprint and subset; deliberately adopt a valid rectangle; inspect before/after masks; explain an incompatible pair; queue one supported comparison; and retry a deliberately lost response without creating another request. Ask what a zero-change or cloud-masked result does and does not establish. Preserve the exact case revision and processing receipt.

Ask the reviewer to locate the intended independent-review action and explain its evidence/limits. Ask the source administrator to identify the owner and recovery path for a blocked source/profile/storage condition. Ask the restricted reader to locate permitted evidence without seeing protected case titles, counts or job references.

Repeat navigation and recovery on 320/390px portrait, short landscape, 200% text and keyboard-only input as relevant. Include a real assistive-technology pass with an appropriate user or specialist. Do not coach users through the primary task; record interventions.

Store session records separately from implementation checks. Report observed success/failure and unresolved issues before updating A19/A20 or any task's user-validation evidence. Absence of a session is NOT_RUN, never PASS.
