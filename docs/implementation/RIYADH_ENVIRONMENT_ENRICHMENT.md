# Riyadh environment enrichment

This qualifies the geographic inputs and inspection workflow for the first bounded Riyadh area (46.732–46.792° E, 24.684–24.744° N). The same capability checks apply when preparing another Saudi or Middle Eastern area. Coverage and accuracy do not transfer from Riyadh to another area.

## Source decisions

- **D01:** [ESA WorldCover 2021 v200](https://esa-worldcover.org/en/data-access), tile N24E045, CC BY 4.0. The complete publisher TIFF is 13,249,205 bytes (SHA-256 `96fa5ddcce3ba36cb96a360678dc66a0873c6c800f6eb5aed52b63f483272213`, S3 ETag `0155f70444210d96d3cddbc4604c45e4-2`). Retain its eleven published classes, no-data mask, native grid and 2021 attribution. The later Sentinel-2 scene provides examples for visual review. Its scene classification has a different purpose and does not validate WorldCover. The release does not qualify ground materials or land-cover change.
- **D02:** [OpenGeoHub GEDTM30 filtered v20250619](https://doi.org/10.5069/G9BV7DT1), CC BY 4.0. The publisher COG is pinned by URL, range response and ETag. The retained asset is a native window, with its own hash, transform, sample mask and receipt. Signed int32 samples use scale 0.1 m and EGM2008. The native grid is 0.00025° and the source model’s declared input period is 2006–2015. The retained Copernicus DSM remains its own source. The comparison uses nearest samples of the ground grid at DSM sample locations, then subtracts in EGM2008 metres. The pinned NGA grid supports the independent interpolation check for ellipsoidal display. The modeled ground and the DSM share some source ancestry. Their differences cannot validate physical accuracy or serve as building heights.
- **D08:** [European Commission JRC GHS-OBAT R2024A V1.0](https://doi.org/10.2905/JRC.9ZB4R6G), ODbL 1.0. The retained 2020 Saudi CSV has archive SHA-256 `23ae88461b39f1cb1aa3f331580deb9940de691234e082f9886ee2b4c8a69188`. A bounded filter selected 25,400 centroids with stable provider IDs, 25,396 modeled heights and four unknowns. The 4,025,726-byte retained subset has SHA-256 `52b2d5abad6bb7a6f62d5508f70740cb6afbce28c0751f17acbd38562c5aecb3`. The estimates are spatial statistics from gridded data. They stay separate from the OpenStreetMap footprints and never supply their extrusion height. The footprint and road audit covers retained features and does not certify source completeness.

[Google Open Buildings Temporal V1](https://developers.google.com/earth-engine/datasets/catalog/GOOGLE_Research_open-buildings-temporal_v1) provided no overlapping 2023 tile in the publisher manifests for the relevant S2 cell. GEOSA and the [Riyadh municipality](https://alriyadh.gov.sa/en/gis-portal) remain candidates for independently controlled terrain and surveyed building dimensions when an exact bounded edition and use rights can be established. FABDEM was not selected for this profile because its download terms require separate review for commercial use.

## Preparation and inspection

1. Pin the source bytes and record the publisher’s edition, receipt, attribution, rights, footprint and acquisition or model period. Use [native GEDTM30 retention](../../scripts/data/retain_gedtm_window.py) and [bounded GHS-OBAT extraction](../../scripts/data/retain_ghs_building_context.py) with explicit source version pins. The original [Riyadh area definition](../../scripts/data/region_profiles/riyadh-reference-v1.json) remains the baseline. Keep imagery, DSM, land cover, ground, the geoid and infrastructure inputs separate.
2. Use the `reference-enrichment-v1` profile. The [versioned preparation tool](../../scripts/data/environment_enrichment.py) verifies source hashes, compares EGM2008 terrain and retains categorical counts, example disagreement locations and dimension evidence. It exposes `toolchain`, `prepare`, `verify` and `rebuild` commands. Existing profiles continue to use their original toolchain.
3. For private staging, set `C4ISR_ENVIRONMENT_ENRICHMENT_TOOLCHAIN` to the digest printed by `python -I /app/scripts/data/environment_enrichment.py toolchain` inside the deployed worker image. Start the optional `environment-enrichment` Compose service with a dedicated scoped credential in `worker-enrichment.token`. Grant the worker access only to the admitted sources needed for the target. Keep the baseline worker, digest and scratch volume independent.
4. Use the [scoped display publisher](../../scripts/ops/publish_enrichment_displays.py) or run the [display processor](../../scripts/data/prepare_enrichment_display.py) against the exact prepared ZIP and manifest digest. Each artifact has a bounded publication request that pins the precise recipe, toolchain and member hashes. The workflow can publish surface and ground meshes, the WorldCover legend, signed differences, imagery and typed vector attributes. Select one raster overlay at a time in the viewer. Vector geometry is draped on the reference surface. A separate quality panel reports modeled building context.
5. Independently verify the prepared ZIP, inspect the release at desktop and compact sizes, and record the actual review decision against the manifest hash. Private qualification does not authorize a portable package, frozen context or simulation export.
